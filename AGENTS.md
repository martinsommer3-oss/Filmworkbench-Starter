# Filmworkbench agent entrypoint — v0.1.1

Read filmworkbench.json, docs/STACK.md and docs/GATES.md. Route a single-image/clip request directly as described there; do not turn it into a full-film assignment. For guided films read docs/GUIDED_FILM.md. For an explicitly autonomous task read docs/AUTONOMOUS_FILM.md and follow its complete loop. Models and exact hashes: docs/model_sources.json. Public node sources and pinned revisions: docs/DEPENDENCIES.md. Separate editing experience: docs/EDIT_NOTES.md; specialized edit tools are not bundled.

## Guided filmmaking

1. Ask what the film should show and agree the scene plan and review mode. Select among K1, K2, K3, K4, K6, K7, K8, K9 and MARKET. Plan the desired visible result, required starting state and visible change before selecting images. Each recipe page contains its references, examples and limitations.
2. Run `python film.py init projects/NAME --recipes ...` in a new folder. Explain the scene order and hard cuts. Prepare coherent cast/location views and changed prop states. Prefer available GPT Image tools; local Krea 2 is a fallback with its own setup. Never assume a skill or subscription supplies access. No paid calls without authorization.
3. For own inputs, copy images/audio into the project and edit each scene's assets mapping in film.json. Read the paired S1/S2 prompt files and adjust both for the same scene, picture roles and dialogue. For K4 also update the prelap WAV/timing. Review pictures and intent with the user before rendering. Templates remain unchanged.
4. Run `film.py check PROJECT` and `film.py check PROJECT --online`. Explain missing nodes/models using the linked upstream sources. `setup_models.py --all` plans all seven weights; downloading requires explicit --download. Follow the user's installation authorization. Use the backend's own Python environment for node dependencies. A matching filename is not proof of matching weights.
5. Run `film.py next PROJECT --comfy-root PATH`. This runs only the next stage. Present its video using the client's supported media display or a file link. Inspect for the agreed action, continuity and visible defects; report uncertainty. S1 audio is used in the finished film.
6. In guided mode wait for the user's acceptance. Only then call `film.py accept PROJECT --job JOB --note "User's decision"`. Never invent approval. Repeat for S2 and subsequent clips. Keep a concise continuity note (owner/count of props, positions, movement and relevant background state) in the project and update only still-pending prompts from the accepted result.
7. A rejected take uses `retry --job JOB`. It preserves outputs but invalidates that job and all later work. Change seed or targeted inputs, then rerender. Do not use stale descendant latents. A timeout leaves the server job running: inspect saved submission and use `recover`, not blind resubmission.
8. After every stage is accepted, `film.py assemble PROJECT` creates the film, S1 audio, recipe prelap and credit. Present the result and any remaining problems. New films do not inherit the examples' translated subtitles.

## Boundaries

Use one GPU producer and one project controller at a time. Do not interrupt unrelated work. Guided mode requires user approvals. In explicitly commissioned autonomous mode the agent performs the documented review loop itself; accept with a hash-bound assessment, never a note-only or blanket approval. Follow the per-stage and total budgets, do not silently increase them. Do not promise persistent world memory, identical rerenders, low-memory compatibility or arbitrary object-level edits. Preserve source files and credentials. Include MiniMax H3 credit and keep H3 output out of model training. Third-party terms remain their own; our code/docs are MIT.

The historical API graphs stay unchanged as evidence. film.py adapts their mask-free H3StageLatent joins to stock AV concatenation, rewrites every external input and latent predecessor, and uses unique output namespaces. It uses public Motion Context, LBH upscaler and geiru_context_suite nodes. The original one-clip render_example.py remains available for a minimal test.
